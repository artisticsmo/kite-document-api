# 09 · 文档解析 API

PRD 1.0 · 2026-10-18 · 付费计算服务 · 有样本与需求后做  
状态：设计提案，未实现/未付款/未提交。先读[总体接入设计](../总体接入设计.md)与[接口事件约定](../接口与事件约定.md)。

## 1. 用户与真实场景

**用户：**需要处理 PDF/扫描件的 Agent 开发者、知识库维护者和资料处理团队。

**第一次使用：**知识库 Agent 收到一份 PDF，需要按页提取文本和表格，保留来源坐标，遇到低质量扫描能定位问题，而不是只得到无法核对的摘要。

**问题：**文件解析结果容易丢页、打乱表格、吞掉不支持内容；模型摘要无法替代原文和定位证据。用户也不想为每个解析供应商独立接付款。

**Kite 接入价值：**出售真实解析和受限 OCR 计算，产物有页码/坐标/置信度与结构。基础解析库可以依赖，独立价值是处理管线、质量分级、证据和可靠交付。

## 2. MVP 范围

**P0，首版必须完成：**

- 首版 PDF，最多 10 页、10MB，支持文本 PDF 与一个限定语言的扫描 OCR；限制值是设计目标，按压测调整。
- 页级文本、表格单元格、坐标与解析方法；低置信度和不支持部分明确返回。
- 上传鉴权、文件版本与解析规格锁定，预检有效页数后给固定报价。
- 有效解析结果保存后结算；首版有界同步，超过规格引导使用后续长任务服务。

**P1，有真实反馈后再做：**

- 在真实样本验证后增加一种格式和语言；每种支持范围独立给出质量报告。
- 复用长任务组件处理更大文件，不在原端点偷偷改成已收费入队。

**首版排除：**不做通用聊天知识库、不判断法律/财务内容正确性、不默认支持所有格式和语言。

## 3. 完整用户流程

1. 应用登录后上传文件，计算输入哈希与页数，执行受限格式预检。
2. 用户选择解析规格和页范围，看到这次任务的固定价格。
3. Passport 按真实示例执行付费解析请求，卖方核对上传所有者与付款主体绑定。
4. 执行解析/OCR，产生有来源定位的结构化产物。
5. 对丢页、空页、不可读页作明确标记，合格报告才结算。
6. 返回结果和问题页，已购买产物可鉴权重复读取。

## 4. Kite 能力接入

| 官方能力 | 接入方式 | 保存与验证 |
|---|---|---|
| 调用 | session execute 带 upload_id/spec_version | upload_id 不是权限凭证，服务自己验证所属用户与付款绑定 |
| 收费 | x402 卖方验证、业务成功后结算 | 按固定页范围/规格报价；不动态超出获批金额 |
| 发现与提交 | service.yaml 与真实例子 | 公开构造 PDF 用作可重跑示例，敏感客户文件不放目录 |

**接入前置：**所有涉及真实付款的路径先完成 G0，固定 network/asset/facilitator/CLI/账户环境；见总体接入设计。真实身份或 Runtime 不可得时明确 blocked，不能用 mock 替代。

**授权边界：**应用与业务权限自己验证；Passport 的 passkey 批准保留给真实用户；本轮 PRD 编制不发起任何授权或支付。协议实例、金额、会话和示例均以现场预检与实际输出为准。

## 5. 接口与数据

**拟提供接口：**POST /uploads 上传；POST /v1/documents/extract 输入 {operation_id,upload_id,spec_version,page_range}；输出 {document_id,input_hash,pages:[{number,text,tables,issues}],parser_version}。上传/读取是本项目鉴权接口，不是 Passport 官方接口。

**核心对象：**Upload、DocumentVersion、ExtractionSpec、PageResult、TableCell、QualityIssue、Artifact、Purchase。输入、解析器版本和参数共同确定一次产物。

operation_id、付款证据、业务版本及产物按公共事件契约关联。接口/包名属于本项目设计，不代表官方已经发布同名能力。

## 6. 状态与恢复

UPLOADED → PRECHECKED → QUOTED → VERIFIED → PARSING → RESULT_READY → SETTLED → AVAILABLE；异常为 corrupt/encrypted/unsupported/over_limit/parse_failed/payment_unknown。

- 加密或损坏 PDF 在收费前拒绝；资源隔离防止压缩/解析炸弹。
- 置信度是模型/引擎估计，不冒充正确率；空页和未解析页不能消失。
- 用户文件按明确保留期处理；复用缓存必须按权限和同一用户范围，不跨用户泄漏内容或用哈希探测文件存在。

任何付款未知均不能通过换 key 自动重买；任何产物恢复都需要原权限。测试桩中的假付款不产生真实交付承诺。

## 7. 开发任务拆分

- 09-T01：收集可公开样本并固定首版语言和质量目标。
- 09-T02：实现上传、预检和报价绑定。
- 09-T03：实现解析、OCR、页级质量与坐标模型。
- 09-T04：实现支付、受权产物及失败分支。
- 09-T05：完成标注评测与真实买方试用。

**投入粗估：**5–7 人周。先做 M0 兼容与样本验证，再做独立核心、真实互通及发布；外部批准、环境开通和审核不计入可承诺工期。

## 8. 界面与使用体验

API 优先，辅助页面左侧原 PDF、右侧结构化内容，点字段能定位页与坐标。

在需要用户决定时展示价格、范围、权限和失败状态；普通产品页面不堆协议实现细节，技术证据留在诊断/报告页。

## 9. 验收与演示

下面是目标，尚未运行或达成。

- F01：准备至少 30 份公开或自有标注样本，按文本、表格、扫描与异常类型分别报告质量，不只给总体分。
- F02：每页都有结果或明确问题；坐标和表格能回到原文核对。
- F03：损坏、加密、超限、越权上传和重复请求各有可重现测试。
- F04：真实付费调用产物可下载并关联原输入；低质量与明确失败的收费处理符合事先合同。

**完整演示：**购买一份含文本、表格和模糊扫描页的解析，展示页码定位和问题页；再上传损坏 PDF 验证收费前拒绝。

**试用观察：**按类型拆分的解析质量、丢页率、实际计算成本、人工修正量与稳定复购需求。

## 10. 提交与独立性

x402 付费服务方向；维护者应证明基础库许可和样本使用权，原创业务不等于重写 OCR。

项目核心包括本 PRD 定义的模型、业务引擎/状态/断言与样本；支付和基础依赖可正常共享，不复制其他参赛实现换名。EC 映射、活动审核与真实贡献是否被统计分别跟踪，不用本 PRD 保证收录。
